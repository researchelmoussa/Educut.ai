Qu’est-ce que le machine learning ?

Tom Mitchell (1997) propose une définition devenue classique : un programme apprend d’une expérience E, pour une tâche T et une mesure de performance P, si sa performance sur T, mesurée par P, s’améliore avec E.

T

La tâche

Ce que le système doit faire.

Exemple RH : prédire si un candidat présélectionné sera embauché après les entretiens.

E

L’expérience

Les données à partir desquelles il apprend.

Exemple RH : 5 000 candidatures passées avec leur issue.

P

La performance

Le critère qui permet de dire s’il fait bien.

Exemple RH : part des candidats retenus par le modèle qui ont réellement été embauchés.

Programmation classique

Règles + données → résultat. Le programmeur écrit les règles : « refuser si moins de deux ans d’expérience ».

Machine learning

Données + résultats → règles. L’algorithme déduit lui-même la règle à partir d’exemples dont on connaît l’issue.

Pour les RH : la définition de P est un choix de gestion, pas un détail technique. Choisir « embauché » comme critère de réussite revient à apprendre les préférences passées des recruteurs, et non la performance future dans le poste.
Réf. H2

Trois manières d’apprendre

La distinction repose sur la nature des données disponibles : connaît-on la « bonne réponse » pour les exemples passés ?

Le plus courant en RH

Apprentissage supervisé

Les exemples sont étiquetés : on connaît le résultat (parti / resté, performance évaluée, embauché / refusé). Le modèle apprend à prédire cette étiquette.

Usages RH : risque d’attrition, présélection, prévision d’absentéisme, estimation d’un salaire de marché.

Explorer

Apprentissage non supervisé

Pas d’étiquette. Le modèle cherche des structures cachées : groupes de profils similaires, thèmes récurrents dans des textes, anomalies.

Usages RH : segmentation des salariés pour une politique de rétention, regroupement thématique de verbatims, détection d’anomalies de paie.

Plus rare

Apprentissage par renforcement

Un agent apprend par essais et erreurs, en recevant des récompenses ou des pénalités selon ses actions.

Usages RH : ajustement progressif des recommandations de formation selon les modules réellement suivis ; affinage des réponses d’un chatbot.

À noter : les LLM combinent plusieurs approches. Ils sont pré-entraînés sur du texte non étiqueté (prédiction du mot suivant), puis ajustés par des exemples supervisés et par renforcement à partir de retours humains.

Observation

Une ligne : un salarié, un candidat, une candidature.

Variables explicatives

Features : les colonnes utilisées pour prédire (ancienneté, salaire…).

Cible

Label : ce que l’on cherche à prédire (départ oui/non).

Jeu d’entraînement / de test

On apprend sur environ 70 à 80 % des lignes et on évalue sur le reste, que le modèle n’a jamais vu.

Surapprentissage

Overfitting : le modèle « apprend par cœur » l’historique et se trompe sur les cas nouveaux.

Variable proxy

Une variable anodine qui révèle indirectement une caractéristique protégée (code postal, prénom, interruption de carrière).

Quatre grandes tâches du machine learning

Avant de choisir un outil, il faut savoir quel type de tâche on lui demande. Chacune correspond à une question différente.

Classification

Question : dans quelle catégorie ?

La sortie est une classe ou une probabilité d’appartenance.

RH : départ oui/non ; CV adapté / non adapté ; ticket RH « paie », « congés » ou « mutuelle ».

Régression

Question : combien ?

La sortie est une valeur numérique.

RH : salaire de marché d’un poste ; nombre de jours d’absence prévus ; délai de recrutement.

Clustering

Question : quels groupes se forment ?

La sortie est un regroupement d’observations proches, sans étiquette préalable.

RH : profils d’engagement ; familles de compétences ; thèmes d’une enquête.

Recommandation

Question : qu’est-ce qui conviendrait ?

La sortie est une liste ordonnée de suggestions.

RH : formations suggérées ; offres internes proposées ; candidats à contacter.

Quelques algorithmes courants

Régression logistique (simple et lisible), arbres de décision et forêts aléatoires, gradient boosting, réseaux de neurones, k-moyennes pour le clustering. Les RH n’ont pas à les maîtriser, mais savoir qu’il existe des modèles plus ou moins explicables aide à négocier avec un fournisseur.

Arbitrage clé : les modèles les plus performants sont souvent les moins explicables. En RH, où il faut pouvoir justifier une décision à une personne, un modèle plus simple et lisible est souvent préférable.

Les spécificités des données RH

Strohmeier souligne que le machine learning en RH ne se pratique pas comme dans le commerce en ligne. Les données RH ont des caractéristiques qui limitent la performance et augmentent les risques.

Petits volumes

Une PME compte quelques centaines de salariés et quelques dizaines de recrutements par an. C’est peu pour apprendre de façon fiable, d’où le recours à des modèles de fournisseurs entraînés ailleurs.

Événements rares

Départs, accidents, fraudes : la classe intéressante est minoritaire, ce qui fausse l’exactitude (voir page précédente).

Critères de réussite flous

Qu’est-ce qu’un « bon » salarié ? Les évaluations de performance sont subjectives et parfois biaisées. Le modèle apprend ces biais.

Biais historiques

Les données reflètent des décisions passées (embauches, promotions) qui ont pu être discriminatoires.

Données sensibles

Santé, syndicat, origine, handicap : catégories particulières protégées par le RGPD et le droit de la non-discrimination.

Contexte changeant

Réorganisations, crises, nouvelles politiques : les régularités du passé cessent de valoir. On parle de dérive des données.

Asymétrie des enjeux : une mauvaise recommandation de film est sans conséquence. Une mauvaise prédiction RH peut coûter un emploi, une promotion ou une formation à une personne. Le niveau d’exigence doit être proportionné.
Réf. H2

Le cycle d’un projet de machine learning en RH

La méthode CRISP-DM, standard de l’analyse de données, décrit six étapes itératives. Les RH sont indispensables aux étapes 1, 2 et 5, et responsables de la 6.

1

Compréhension du besoin

Quelle décision RH veut-on éclairer ? Quel bénéfice attendu ?

rôle RH clé
2

Compréhension des données

Quelles données existent, avec quelle qualité, sur quelle base juridique ?

rôle RH clé
3

Préparation

Nettoyage, choix des variables, retrait des variables sensibles et proxys.

4

Modélisation

Choix et entraînement de l’algorithme.

5

Évaluation

Performance, équité entre groupes, explicabilité, utilité métier.

rôle RH clé
6

Déploiement et suivi

Intégration au processus, formation, contrôle dans la durée.

Questions RH à l’étape 1

Quelle décision change si le modèle fonctionne ? Qui l’utilisera ? Que fait-on d’une alerte ?

Questions RH à l’étape 5

Le modèle se trompe-t-il davantage pour les femmes, les seniors, les temps partiels ? Peut-on expliquer un résultat à un salarié ?

Questions RH à l’étape 6

Qui surveille la performance ? Quand réentraîne-t-on ? Comment un salarié conteste-t-il ?

Cadrer un problème RH en problème de machine learning

Le canevas ci-dessous est celui de l’activité. Il est rempli ici pour un cas différent : prévoir l’absentéisme de courte durée dans un centre logistique.

RubriqueExemple rempli
Décision RH viséeAjuster chaque semaine le volume d’intérimaires pour éviter les sous-effectifs.
CibleNombre de jours d’absence de moins de 3 jours par équipe la semaine suivante (régression).
Variables envisagéesHistorique d’absence par équipe, saison, jours fériés, charge prévue, météo. Exclues : données de santé et absences individuelles nominatives.
Données et qualité3 ans d’historique dans le SIRH temps ; codes d’absence harmonisés depuis 2 ans seulement.
Type d’apprentissageSupervisé (on connaît l’absentéisme réel des semaines passées).
Mesure de performanceÉcart moyen entre absences prévues et réelles ; comparaison avec la prévision actuelle du manager.
Risques et garde-fousGlissement vers un suivi individuel : prédiction au niveau de l’équipe uniquement, information du CSE, analyse d’impact (AIPD) si nécessaire.
Remarque : le niveau d’agrégation (équipe plutôt qu’individu) est un choix de conception qui réduit fortement les risques sans sacrifier l’utilité.

À retenir

  • Le ML déduit des règles à partir d’exemples : données + résultats → modèle.
  • Supervisé (on connaît la réponse), non supervisé (on cherche des structures), par renforcement (essais et récompenses).
  • Quatre tâches : classification, régression, clustering, recommandation.
  • Quand l’événement est rare, l’exactitude trompe : regarder précision et rappel.
  • Les données RH sont petites, biaisées, sensibles et changeantes.
  • Les RH sont responsables du cadrage, de l’évaluation et du suivi.
